## 1. Smallest complete journey

Use one prepared native issue with a supplied Linear context snapshot. Preserve
several attributable opinions when selected, one accountable Council final reviewer
and an executor distinct from that reviewer. Serial consultations are sufficient to
exercise that composition; no voting or parallel fan-out framework is necessary.

1. **Bind the case.** The owner selects current mandate, exact team/council revisions,
   authorized participants, covered native path, numeric limits and an actual owner
   destination. Council stores context/criteria revisions and confirms prerequisites.
2. **Capture approach and opinions.** Executive produces bounded contributions for
   Council-reserved slots, retaining each profile/method version, evidence, limitations
   and dissent. A preexisting L02 contribution is reusable only after freshness and
   reference validation; it does not reserve a new call or authorize execution.
3. **Decide continuation.** Council records an attributable direction on the approach
   and current mandate. Proceed releases one bounded executor segment only after its
   native effect is confirmed. Revise/refuse/escalate release no affected execution.
   These are proposed semantic outcomes, not existing native verdict enum values.
4. **Submit V1.** The executor identifies an immutable repository/commit/artifact and
   evidence set. Council pins author, review subject, current criteria/mandate revision
   and review composition. It validates accessible bytes and current candidate identity.
5. **Request a bounded correction.** Council records a demonstrated must-fix gap,
   preserved criterion, smallest sufficient change and verification method. Its durable
   admission claim consumes the correction allowance before dispatch. Native effect
   returns work to the executor; optional useful-now/deferred suggestions do not block
   a sufficient result by themselves.
6. **Submit and review V2.** A new immutable subject receives its own review, focused
   on corrections and affected behavior. V1 acceptance cannot carry over. Unchanged
   findings alone cannot justify another unlimited round.
7. **Decide and confirm effect.** The authorized final reviewer applies the stored
   result decision through the qualified native path. Council distinguishes recorded,
   applying, confirmed, refused and unknown observations. Executive displays the
   canonical IDs and readback, not an independent acceptance state.
8. **Recover or stop.** After interruption, reconcile persisted intent, native decision,
   effect and unsettled usage before any new admission. Exhaustion blocks further work
   and reaches the owner. Already running work remains visible until observed stopped
   or finished. Unknown effect is never reconstructed from an agent summary.

A nominal sufficient result may skip correction. Qualification must additionally
exercise V1 → correction → V2 and an exhausted-limit/restart case. Council approval
accepts the identified result; it does not authorize Git merge, deployment, publication
or Linear status mutation.

**One dispatch owner per operation:** Council is the scheduler/admission authority for
the governed journey. For an Executive contribution slot, Council persists and
reserves the operation; Executive is the sole physical session/send owner. Council
collects its persisted result and never also sends that slot itself. Council/native
execution owns executor and final-reviewer wakeups under separate correlated intents.
If Council instead uses a method directly, label that as a different operation and do
not also invoke Executive for the same slot. The bridge/authentication contract for
reserved slots must be implemented explicitly: E's existing board-owner action does
not already authorize Council-agent dispatch. Do not impersonate the owner.

L03 includes the controls indispensable at direction, review, correction and resume
boundaries: current mandate, durable attempt admission, bounded native calls, persisted
limits, uncertainty and owner escalation. It excludes L04's general progress/drift
signals, recurring supervision, broad watchdog/scheduler machinery and full B03–B05
release evaluation. L04 must not become a place to defer L03's counters, readback or
no-redispatch guarantee. A required run bound without a qualified control blocks the
affected L03 path now.

Other exclusions: automated Linear intake/sync, catalogue duplication, profile edits
in this lot, voting/appeals framework, automatic hiring, external delivery control,
general accounting engine, automatic retries and claims of measured savings.
